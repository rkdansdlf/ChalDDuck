# 사용자 노출 용어 기준

**사용자에게 보이는 한국어**의 기준 어휘입니다. 화면·알림·오류 문구·라벨·aria 라벨이
여기에 없는 말을 쓰면 문서와 코드가 어긋나고, 같은 개념을 두 이름으로 부르게 됩니다.

코드 주석과 식별자(`purify`, `drainCushions`, `confirmDue`)는 이 표의 대상이 **아닙니다.**
바꿀 이유가 없고, 바꾸면 import·테스트 픽스처·검색성만 흔들립니다. 화면이 쓰는 이름만
기준에 맞춥니다.

## 표

| 개념 | 기준 용어 | 이르지 말 것 |
| --- | --- | --- |
| 개인의 활동 기록 | **기여 기록** | 기여도 (점수·비율을 연상시킴) |
| 고르고 싶은 역할 | **희망 역할** / 희망자 | 희망 순위, 1순위 희망 *(문서에서만)* |
| 최종 배정된 역할 | **확정된 역할** / 확정 | 합의한 역할 |
| 추첨 결과 받기 | **받기** | 수락하기 |
| 추첨 결과 거절하기 | **안 받기** | 거절하기 |
| 읽는 쪽 AI 도움 | **읽기 도움** | 순화, 순화해서 읽기 |
| 다듬어진 읽을 말 | **다듬어 읽은 말** / 다듬어 읽음 | 순화문, 순화됨 |
| 쓰는 쪽 AI 도구 | **쿠션 번역기** / 쿠션 번역 | 읽기 도움 (다른 기능임) |
| 팀원이 확인할 차례 | **팀원 확인 대기** | 확인 대기 |
| 팀장이 재입장을 막기 | **거절** | 안 받기 *(역할 쪽 말임)* |

**읽기 도움과 쿠션 번역기는 합치지 않습니다.** 둘은 이름이 비슷하지만 방향이 반대입니다 —
읽는 사람을 위한 것과 쓰는 사람이 사용하는 것입니다. 합치면 어느 쪽인지 사라집니다.

## 규칙

**상태 문구는 다음 행동을 하는 사람을 밝힙니다.** `확인 대기`만 있으면 내가 해야 하는지
팀장이 해야 하는지 알 수 없습니다. `팀원 확인 대기`처럼 주체를 넣습니다. 길어지면 화면
위치로 생략합니다 — 시트 안의 목록 등 이미 맥락이 있는 곳.

**예외 두 곳은 의도적으로 다릅니다.** 역할 추첨은 내가 맡을지 결정하므로 `받기 · 안 받기`,
재입장은 팀장이 다른 사람의 접근을 허용할지 결정하므로 `승인 · 거절`입니다. reject 계열을
기계적으로 같은 말로 맞추지 않습니다.

**'추첨'과 '정하기'는 다른 기능에서도 재사용됩니다.** 역할 추첨, 메뉴 룰렛, 마감 정하기가
각각 자기 자리에서 쓰는 말입니다. 같은 화면 안에서 둘이 붙지 않게 합니다.

## 지킨 방법

문서만으로는 막히지 않습니다. 새 화면에서 `기여도`나 `순화`, `수락하기`가 다시 생기는 것까지
막는 것은 코드에 둔 검사가 해야 합니다. `scripts/smoke.mts` 에 주석을 걸러 내고
`기여 기록` · `읽기 도움` · `받기` 가 남아 있는지를 보는 불변식을 두면 됩니다.
