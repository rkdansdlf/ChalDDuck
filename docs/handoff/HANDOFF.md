# Handoff: 찰떡(ChalDduck) 팀플 앱 — 프론트 설계 v3 (33화면 프로토타입)

## Overview
찰떡은 대학생 팀 프로젝트(팀플)를 위한 AI 기반 협업 앱입니다. 이 핸드오프는 기존 기획안(PDF 18화면 + 보완 문서)을 대조·보완하고, 5주간 디자인 고도화(색상 토큰, 내비게이션 재구성, 공통 컴포넌트화, 반응형 예시)를 거쳐 만들어진 **33개 화면의 클릭 가능한 HTML/React 프로토타입**을 실제 코드베이스로 옮기기 위한 자료입니다.

## About the Design Files
이 폴더의 HTML/JSX 파일은 **디자인 참고 자료(design reference)**입니다 — 실제 서비스에 그대로 붙여 넣을 프로덕션 코드가 아니라, 의도한 모습과 동작을 보여주는 프로토타입입니다. React를 CDN(UMD) + Babel 인라인 변환으로 실행하는 간이 환경이며, 상태는 브라우저 새로고침 시 초기화되고 서버·DB·인증이 전혀 없습니다.

**할 일은 이 HTML 디자인을 대상 코드베이스(리액트 네이티브, Next.js, Flutter, SwiftUI 등 실제 서비스가 쓰는 스택)의 기존 패턴·라이브러리로 다시 구현하는 것**입니다. 아직 정해진 스택이 없다면, 이 프로토타입의 구조(웹 기반 반응형, 5탭 구조)에 가장 적합한 프레임워크를 선택해 구현해 주세요.

## Fidelity
**Hifi(고정밀)에 가까운 중간 단계**입니다. 색상·타이포·spacing·컴포넌트 스타일은 최종안으로 확정된 값이지만, 다음은 실제 구현 단계에서 다시 검증이 필요합니다.
- 데모 데이터는 전부 하드코딩(가짜 이름·날짜·메시지)이며 실제 데이터 모델이 아닙니다.
- "미확정" 항목은 화면 안에 `[검토] 기획안에 규칙 없음 · 확인 필요` 점선 박스(기본 숨김, 토글로 표시)로 명시되어 있습니다 — 아래 "확정되지 않은 정책" 섹션에 모아 정리했습니다.
- 파일 뷰어(22번)는 이미지 파일만 실제로 열리고, PDF·PPTX 등은 "미지원 형식" 안내만 있습니다(진짜 뷰어 미구현).
- 33번(PC 3분할 채팅) 화면은 실제 반응형 브레이크포인트 전환이 아니라 큰 화면에서 어떻게 보여야 하는지의 **정적 예시**입니다.

## 공통 컴포넌트 시스템 (`ui.jsx`)
모든 화면이 공유하는 프리미티브입니다. 실제 구현에서는 이 목록을 대상 프레임워크의 컴포넌트 라이브러리로 1:1 대응해 만드는 것을 권장합니다.

- **Phone**: 390×812 모바일 프레임 컨테이너 (배경 `--page`, radius 34, `--sh-lg` 그림자)
- **Status**: 상태바(9:41, 신호·와이파이·배터리 아이콘)
- **Bar**: 상단 앱바 — `title`(15px/600), `sub`(13px/500, muted), 뒤로가기(44×44), 우측 action 아이콘
- **Body**: 스크롤 본문. `dense`(좌우 16px)=목록/시간표, 기본(좌우 20px)=소개/입력 화면
- **TabBar**: 하단 5탭 — **홈 / 채팅 / 일정 / 드라이브 / 팀** (아이콘: house / messages-square / calendar-check / folder-open / users-round). 활성 탭은 위에 노란 바(`--y-400`) + 굵은 라벨. `pending` prop으로 탭별 배지 숫자
- **Panel**: 카드 표면. `s` variant = card/fill/cream/yellow/coral/sel/raise, 기본 radius 20, pad 16
- **Rows**: 연속 목록 — 카드 하나 + 항목 사이 구분선(카드를 겹겹이 쌓지 않음)
- **SecTitle**: 섹션 제목(15px/700) + 보조 설명(13px/500, muted) + 우측 액션 링크
- **Btn**: variant primary/yellow/outline/soft/ghost/off. size lg=52px, 기본(md)=44px, sm=44px보다 작음(패딩만 축소, 보조 동작 전용). radius 14
- **Chip**: 상태 라벨(항상 아이콘+텍스트 동반, 색만으로 구분하지 않음). tone n/ok/warn/err/want/veto/y
- **STATUS / StatusBadge**: 드라이브·버전·할 일 전체가 공유하는 상태 어휘 — `none`(미입력)/`todo`/`waiting`(대기)/`doing`(진행 중)/`done`(완료)/`late`(마감 후 제출)/`failed`(실패)/`ready`(준비 중). 각 상태는 고정된 tone+icon 조합
- **Note**: 안내·고지 배너. tone info(파란, `--info`/`--info-bg`)/y/warn/err
- **Undecided**: `[검토] 기획안에 규칙 없음 · 확인 필요` 점선 박스 — **기본적으로 화면에 렌더링되지 않음**(`useReviewMode()` 훅이 `window.__CD3_REVIEW__` 전역 플래그를 읽음). 개발자 도구 상단의 "검토 메모 표시/숨김" 토글로만 켜짐 — 사용자 화면과 검토 메모를 분리하기 위한 장치이므로, 실제 구현에서는 이 내용을 사용자에게 보여주지 말고 개발 문서로만 참고
- **CompareCard**: AI 도구 공통 — 원문/결과 두 칸(모바일 세로 스택, 데스크톱은 `flex-wrap`으로 자동 좌우 배치), 결과 칸에 "AI 초안" 배지(`Chip tone="y" icon="sparkles"`) 고정 부착. 15·20·26·27번이 공유
- **Avatar**: `mbti`가 있으면 `assets/characters/<MBTI>.png` 원형 이미지, 없으면 이름 첫 글자 모노그램(점선 원)
- **Field / Input**: 라벨(14px/700) + 입력창(최소 높이 52px, radius 14, 테두리 `--input-border` 전용 색상)
- **Dock**: 탭바 위에 고정되는 하단 액션 바(주요 CTA)
- **Sheet**: 하단에서 올라오는 모달(radius 28 상단, 배경 `rgba(36,28,20,.38)` 오버레이)
- **Toast**: 하단 임시 알림(탭바 위 88px, `--ink-800` 배경)
- **Progress**: 온보딩 단계 표시 바

## 상태 관리 (현재 프로토타입 기준)
데모는 `App`(app.jsx) 최상위에서 `useState`로 모든 화면 간 공유 상태를 보관합니다 — 실제 구현에서는 다음을 전역/서버 상태로 옮겨야 합니다.
- `name, mbti, picks(4문항), want, veto` — 온보딩 입력값
- `versions[]` — 파일 버전 배열(복원 시 새 항목을 맨 위에 추가, latest 플래그 갱신)
- `myContrib[], teamCheck[]` — 기여도 기록(자동 수집 vs 본인 추가, 팀원 확인 상태)
- `fix` — 기여 기록 추가/정정 화면의 모드(`{mode:"add"|"resolve", ...}`)
- `dmTarget` — 현재 열려 있는 DM 상대
- `review` — 검토 메모(Undecided 박스) 표시 여부, `window.__CD3_REVIEW__` 전역과 동기화
- 화면 내부 지역 상태(각 `Scr*` 컴포넌트에 위치): 07번의 `resolve`/`rejected`(역할 추첨 결과·제외 명단), 09/10번의 `stage`("proposed"/"confirmed")·`carried`(이월 여부), 19/31번의 `msgs`(전송 실패 시뮬레이션 포함), 21번의 `tasks`(상태 순환 todo→doing→done)

## 인터랙션 요약
- **네비게이션**: `go(screenKey)`가 화면 전환 + 해당하는 탭을 자동 활성화. `onTab(tabKey)`는 탭 클릭 시 그 탭의 대표 화면으로 이동(홈→home, 채팅→chatHub, 일정→mytime, 드라이브→drive, 팀→roster)
- **역할 추첨(07)**: 겹치는 역할마다 "추첨하기" → 랜덤 도구 선택 시트 → 당첨자 결정 → **수락**(확정) 또는 **거절**(당첨자를 제외 명단에 추가하고 재추첨 가능하게 리셋)
- **회의 확정(09/10)**: 후보 선택 → "제안" → `proposed` 상태(응답 마감 표시) → "동의하기"(확정) 또는 "참석 어려움 알리기"(미확정으로 롤백). 전원 불가 시엔 "다음 주로 이월 확정하기"로 즉시 이월 상태 전환
- **파일 복원(22)**: 복원 확인 시트 → 새 버전 번호로 추가(기존 버전 유지, latest만 갱신)
- **채팅 전송 실패**: 전송 시 25% 확률로 `status:"failed"` 데모 — 실패한 메시지에 "전송 실패 · 다시 보내기" 버튼
