# 찰떡 (ChalDduck)

대학생 팀 프로젝트(팀플)를 위한 협업 앱. 가입·로그인 없이 **초대 코드 + 이름**으로 들어와서
역할을 조율하고, 회의 시간을 잡고, 자료를 모으고, 기여 기록을 남깁니다.

디자인 핸드오프(33화면 프로토타입)를 실제 코드베이스로 옮기는 중입니다.

## 스택

| | |
|---|---|
| 프레임워크 | Next.js 16 (App Router) · React 19 · TypeScript |
| 스타일 | Tailwind CSS v4 + CSS 변수 디자인 토큰 |
| 아이콘 | lucide-react (직접 등록한 것만 번들에 들어감) |
| 서체 | Pretendard Variable (저장소에 포함, `next/font/local`) |
| 데이터 | PostgreSQL (Supabase) + Prisma |
| AI | OpenRouter (기본 `openrouter/free`) |
| 서버 | Next.js Server Actions |

### 처음 실행

```bash
npm install
```

`.env` 를 만들고 Supabase 대시보드 > Connect 의 값으로 채웁니다
(`.env.example` 참고 — 커밋되지 않습니다).

```bash
npx prisma migrate dev --name init   # 표 만들기
npm run db:seed                      # 데모 팀 한 개 넣기
npm run dev
```

`DATABASE_URL` 은 런타임용 **트랜잭션 풀러(6543)**, `DIRECT_URL` 은 마이그레이션·시드용
**직결(5432)** 입니다. 풀러로는 prepared statement 와 DDL 잠금을 못 버텨 마이그레이션이 깨집니다.

런타임 커넥션 풀은 [`src/server/db.ts`](src/server/db.ts) 에서 직접 만듭니다 — 쉬고 있던
연결이 끊겼을 때 프로세스가 죽지 않게 받아 주고, 순간적인 연결 실패(P1001·P2024)는
짧게 두 번 다시 시도합니다. 자세한 이유는 그 파일 주석에 있습니다.

  한 바퀴가 다 돕니다. 자기 기록은 자기가 확인할 수 없습니다
- **21 / 24 할 일** — 체크리스트와 익명 콕 찌르기(업무당 하루 한 번)
- **28 / 29 팀 친목** — 아이스브레이킹, 메뉴 룰렛
- **33 채팅 PC 화면** — 1024px 이상에서 목록·대화·정보 3분할 (아래 참고)
- **반응형 앱 셸** — 모바일 하단 탭바 ↔ 데스크톱 세로 막대 (아래 참고)

**핸드오프의 33개 화면을 모두 옮겼습니다.**

> **AI 도구는 `OPENROUTER_KEY` 가 있을 때만 모델을 부릅니다.** 키가 없으면 앱은 그대로
> 돌아가고 도구는 미리 적어 둔 샘플을 돌려주며, 화면이 "아직 AI가 연결되지 않았습니다"라고
> 그대로 알립니다 — 샘플을 AI 결과인 척 보여 주지 않습니다.

## 반응형

| 폭 | 레이아웃 |
|---|---|
| ~599px | 뷰포트를 꽉 채우고 **하단 5탭**으로 이동 |
| 600~1023px | 본문이 860px 까지만 넓어지고 가운데 정렬 · 하단 탭바 유지 |
| 1024px~ | 탭바가 **왼쪽 세로 막대**로 바뀌고 본문에 폭을 내줌 |

폭이 생기면 화면도 그에 맞게 바뀝니다 — 홈은 두 기둥, 드라이브 제출함은 두 줄,
기여도 리포트는 A4 비율, 08 시간표 격자는 칸이 44px 로 커져 최소 탭 영역을 지킵니다.

온보딩은 탭이 없는 집중 흐름이라 넓은 화면에서도 420px 카드로 모읍니다 —
입력칸 하나가 화면 폭만큼 늘어나면 읽기 어렵습니다.

**채팅(33번)은 넓은 화면에서 실제로 3분할로 동작합니다.**

| 폭 | 채팅 |
|---|---|
| ~1023px | 화면을 한 번에 하나씩 (32 → 19 / 31) |
| 1024px~ | 목록 + 대화 |
| 1280px~ | 목록 + 대화 + 자료·정보 |

1024px 에서 세 기둥을 다 펴지 않는 이유는 왼쪽 앱 내비게이션이 232px 을 이미 쓰기 때문입니다 —
거기서 세 기둥을 펴면 대화 칸이 말풍선 한 줄도 못 담습니다.

## 남은 일

핸드오프의 화면은 모두 옮겼습니다. 제품이 되려면 다음이 남아 있습니다.

### 1. 서버 이관 (끝)

**읽기도 쓰기도 전부 데이터베이스**를 거칩니다. 브라우저 안에만 남아 있는 상태는 없습니다.

| 옮긴 것 | 위치 |
|---|---|
| 팀 만들기 · 입장 · 세션 | `server/actions/onboarding.ts` |
| 역할 추첨·수락·거절 | `server/actions/roles.ts` |
| 회의 제안·응답·확정·이월 | `server/actions/meetings.ts` |
| 파일 복원(새 버전 추가) | `server/actions/drive.ts` |
| 기여 기록 추가 · 정정 응답 | `server/actions/contrib.ts` |
| 할 일 추가·상태 변경 · 콕 찌르기 | `server/actions/tasks.ts` |
| 내 시간표 저장 | `server/actions/schedule.ts` |
| 메시지 보내기 · 읽음 표시 | `server/actions/chat.ts` |
| AI 도구 호출 자리 | `server/actions/ai.ts` |

온보딩 중에만 쓰는 `features/onboarding/onboarding-state.ts` 는 남겨 뒀습니다 —
아직 팀에 저장되기 전의 선택이라 서버로 보낼 것이 없습니다.

### 1-1. 회의 응답 마감

마감은 시각이 지나면 저절로 오는 일이라 아무도 앱을 열지 않아도 지나갑니다. 두 겹으로 둡니다.

- **화면은 계산해서 보여 줍니다.** `effectiveStage()` 가 "마감이 지났고 반대가 없으면 확정"을
  그 자리에서 판단하므로, 예약 작업이 늦게 돌아도 지나간 마감이 "대기 중"으로 보이지 않습니다.
- **표는 예약 작업이 맞춥니다.** `/api/cron/meetings` 를 주기적으로 부르면 마감이 지난 제안을
  `confirmed` 로 바꿉니다(`vercel.json` 에 15분 간격으로 등록). 다른 데 올린다면 어떤
  스케줄러로든 이 주소만 부르면 됩니다. `CRON_SECRET` 이 없으면 **항상 401** 입니다.

마감이 지난 뒤의 반대는 서버가 거절합니다 — 받아 주면 이미 확정된 회의가 뒤집힙니다.
24시간을 기다리지 않고 마감 뒤 화면을 보려면 09 화면의 "마감 지금으로 당기기 (데모)"
버튼을 쓰세요(개발 환경에서만 보입니다). **확정하지 않고 시계만 당기므로** 그 버튼으로 본
화면이 실제 마감 뒤의 화면과 같습니다.

### 1-2. 인증

가입·로그인은 없습니다. 대신 **팀에 들어오는 모든 길의 마지막 문을 팀장이 엽니다.**
팀장이 초대 코드를 보냈든 본인이 요청했든 같습니다 — 코드가 한 번 새면 누구든 팀의
기여 기록과 대화를 볼 수 있기 때문입니다.

| 상황 | 흐름 |
|---|---|
| **처음 들어오기** | 이름·MBTI·희망 역할을 고르고 요청 → 팀장이 승인하면 자동으로 들어감 |
| **팀을 만든 첫 사람** | 승인해 줄 팀장이 없으므로 바로 들어가고, 그 사람이 팀장이 됨 |
| **재입장 (같은 이름, 새 기기)** | 아래 두 길 |

이미 있는 이름으로 새 기기에서 들어오려면 둘 중 하나를 거칩니다.

| 길 | 언제 |
|---|---|
| **재입장 코드** | 첫 입장 때 한 번 보여 준 코드를 적는다. 서버에는 해시만 남는다 |
| **팀장 승인** | 코드가 없을 때. 팀장 화면에 요청이 뜨고 승인하면 저절로 들어간다 |

**팀장은 팀을 만든 사람**입니다(`Member.isLeader`). 만든 브라우저에 표시를 남겼다가
그 브라우저가 온보딩을 마칠 때 세웁니다.

같이 막은 것:

- **온보딩의 `upsert` 를 없앴습니다.** 예전에는 남의 이름을 적으면 기록을 이어받았고,
  그 과정에서 상대의 희망 역할·Veto 까지 덮어썼습니다 — 역할 추첨의 입력이 바뀌는 일입니다.
- **초대 코드를 6자리로** 늘렸습니다. 4자리는 32⁴ ≈ 105만이라 `/join?code=` 를 훑어
  실제 팀을 찾아낼 수 있었습니다. 6자리면 32⁶ ≈ 10억입니다.
- **세션이 서버에서도 만료됩니다**(90일). 쿠키 만료만 믿으면 쿠키 값을 한 번 얻은 쪽이
  영원히 씁니다.
- 재입장 코드를 연속으로 틀리면 10분 잠깁니다.

`/team/access` 에서 내 기기를 보고 내보낼 수 있고, 재입장 코드를 새로 받을 수 있습니다.

**팀장은 그냥 나갈 수 없습니다.** 팀장이 사라지면 새 기기 재입장을 승인해 줄 사람이 없어
팀원들이 기기를 바꾸는 순간 잠깁니다. 그래서 나갈 때 둘 중 하나를 골라야 합니다.

| 길 | 결과 |
|---|---|
| **팀장 넘기고 나가기** | 팀원 한 명을 골라 넘기고 나간다. 프로젝트는 그대로 |
| **프로젝트 없애기** | 팀이 통째로 사라진다. 되돌릴 수 없어 팀 이름을 직접 적어야 한다 |

넘기기만 하고 팀에 남을 수도 있습니다.

**나가도 `Member` 행은 지우지 않고 `leftAt` 만 찍습니다.** 기여 기록·메시지·파일 이력이
성적 근거라, 사람이 나갔다고 팀 기록에 구멍이 나면 안 됩니다. 명단과 집계에서만 빠지고,
같은 이름으로 다시 들어오면(재입장 문을 거쳐) 명단에 되돌아옵니다.

**추방은 두지 않습니다.** 팀에 있는 사람은 어차피 초대 코드를 받아 들어온 사람이고,
잘못 들어온 경우는 팀장이 재입장을 승인하지 않는 것으로 이미 막힙니다.

시도 제한은 프로세스 메모리에 있어 인스턴스가 여러 개면 인스턴스마다 셉니다 —
실제 배포에서는 공용 저장소(Redis 등)가 필요합니다.

### 2. AI 연결 (붙었음 — 남은 것은 운영)

도구 5종이 [`server/ai/tools.ts`](src/server/ai/tools.ts) 에서 Claude 를 부릅니다.
프롬프트가 곧 제품 약속이라 그 파일에 약속을 함께 적어 뒀습니다 — 쿠션 번역기가 마감을
늦춰 적거나 AI 서기가 정해지지 않은 담당자를 채우면 그건 버그입니다.

**리서처만 웹 검색을 붙였습니다.** "출처가 없는 결과는 보여주지 않는다"가 약속인데 검색
없이 물으면 있을 법한 논문 제목과 학회지 이름을 지어냅니다. 그래서 검색 결과에서 실제로
인용된 주소를 가진 카드만 남깁니다 — 프롬프트가 아니라 코드가 거릅니다.

**모델은 `.env` 의 `OPENROUTER_MODEL` 로 고릅니다.** 기본값 `openrouter/free` 는 무료 모델
하나를 요청마다 무작위로 고르는 라우터입니다. 돈은 들지 않지만 **같은 요청이 899초(실패)·
5.3초·3.9초로 갈렸고**, 담당자 자리에 `null` 대신 빈 문자열을 넣는 등 지시를 덜 정확히
따릅니다. 그래서

- 요청마다 `AbortSignal` 로 60초에 끊습니다(`OPENROUTER_TIMEOUT_MS` 로 조절).
  SDK 의 `timeout` 만으로는 위의 899초가 끊기지 않았습니다.
- `tools.ts` 가 모델 출력을 그대로 믿지 않습니다 — 빈 담당자는 "미정"으로 돌리고,
  인용되지 않은 주소가 붙은 자료 카드는 버립니다.

품질이 필요하면 `OPENROUTER_MODEL="anthropic/claude-sonnet-5"` 처럼 유료 슬러그로 바꾸세요
(실측 3~6초, 5종 모두 규칙대로 동작 확인).

아직 남은 것:

- **AI 이용·보관 정책이 화면에만 있습니다.** 허브가 "대화 내용은 90일 보관 후 자동 삭제"
  라고 적고 있지만 입력을 저장하지도, 삭제하지도 않습니다. 저장을 시작하면 그때
  `AI_POLICY.retentionDays` 를 실제로 지키는 작업이 필요합니다.
- **사용량 한도가 없습니다.** 호출마다 비용이 들고 세션 확인만 붙어 있습니다.
  팀당·일당 상한을 둘지는 정해지지 않았습니다.
- AI 사용 내역 내려받기 버튼은 아직 자리만 있습니다.

### 2-1. 파일 저장소

파일은 Supabase Storage 의 **비공개 버킷**(`submissions`)에 들어갑니다. 버킷은
`npm run db:storage` 로 한 번 만듭니다.

이 앱은 Supabase Auth 를 쓰지 않아(가입·로그인이 없는 제품입니다) 저장소 RLS 가 판단할
사용자가 없습니다. 그래서 **접근 권한은 앱이 서버에서 직접 확인하고**, 내려받기는 60초짜리
서명된 주소로만 내줍니다. 서비스 롤 키는 `server/storage/` 안에서만 쓰이고 브라우저로
나가지 않습니다.

- 한 파일 50MB, 문서·이미지·PPT·PDF 만 받습니다.
- 저장소 객체는 **버전마다 하나**입니다. 같은 경로에 덮어쓰면 옛 버전을 내려받을 때 새
  내용이 나와, 목록만 역사이고 내용은 하나인 가짜 버전 기록이 됩니다.
- 복원은 새 객체를 만들지 않고 **같은 객체를 가리키는 새 버전**을 더합니다.

**제출함 → 파일 목록 → 버전 기록**으로 한 단계가 늘었습니다. 핸드오프는 제출함에 파일이
하나뿐이라고 보고 곧장 버전 기록으로 들어갔는데, 실제로 올릴 수 있게 되면 한 제출함에
발표자료와 대본이 같이 들어갑니다.

### 3. 확정이 필요한 정책

`?review=1` 로 켜면 화면 안 `[검토]` 박스가 모두 보입니다. 특히 다음 세 가지는
서버를 붙이기 전에 정해야 합니다.

- 회의 참여를 무엇으로 판정하는지(입장 여부·발언 여부·시간)
- 의견 차이가 끝까지 안 좁혀졌을 때의 최종 기재 방식. 또 **누가 정정에 응답할 수 있는지**가
  정해지지 않아 지금은 팀원 누구나 가능합니다(서버는 같은 팀인지만 확인합니다).
- **몇 명이 확인해야 기록이 확정되는지.** 지금은 한 명입니다 — 전원으로 두면 한 사람이
  답하지 않을 때 영영 확정되지 않습니다(`server/contrib/state.ts` 의 `CONFIRMS_NEEDED`).
